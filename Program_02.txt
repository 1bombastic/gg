PROGRAM 2:
Uploading Documents and Images using Amazon S3.
Step-1:
Sign in to the AWS Console and search for S3. Open the Amazon S3 service.
Step-2:
Choose Create bucket. Enter a globally unique bucket name using lowercase letters, numbers, and hyphens. For example, use a lab-specific name with a unique suffix rather than copying a name that may already exist.
Step-3:
Select the required AWS Region. Note the Region because it is relevant when locating the bucket and configuring other resources.
Step-4:
Keep Block all public access enabled for ordinary file storage. Public access is not needed to upload or download files while signed in with suitable permissions.
Step-5:
Review the remaining settings, such as bucket versioning and encryption, according to the lab instructions. Use the default encryption settings unless your instructor specifies otherwise.
Step-6:
Under Instance type, select a type supported in the selected Region, such as t2.micro or t3.micro when available and eligible for your account.
Step-7:
Choose Upload, then Add files. Select one or more sample documents, PDFs, and image files from your computer.
Step-8:
Review Network settings. Select the required VPC and subnet. For SSH access to a Linux instance, allow TCP port 22 only from your own public IP address rather than from all IP addresses.
Step-9:
Review the selected filenames. If the console offers optional permissions or properties, do not grant public access unless the experiment explicitly requires it.
Step-10:
Review the summary on the right side and click Launch instance. Wait for the success message and open the instance details.
Step-11:
Click Upload and wait for the upload status to show success. If an upload fails, check the displayed error and verify that your account has permission to upload objects.
Step-12:
Return to the Objects list and confirm that each uploaded file is visible. Select a file to view its key, size, last-modified time, and other object properties.
Step-13:
Select an object and use Download to verify that the file can be retrieved. You can also open the object's details to inspect its S3 URI.
